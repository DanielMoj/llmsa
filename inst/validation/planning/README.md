# Planning-rule validation resources

These are class A documentation results for K-M3c-6, generated by
`validation/sim/planning_rule.R`. They are separate from the operator's class B
studies. The vignette reads the files; it does not simulate during its build.
The harness independently repeats the study in
`tests/simulation/test-plan-satterthwaite.R` and checks the displayed numbers.

ADEMP:

* **Aim:** quantify the precision of the estimated prompt variance and compare
  its empirical coefficient of variation with the planning rule in ANK-89.
* **Data:** independent normal crossed effects with the S-boot-1 components
  from `docs/02-statistikkern.md`. ADR-054 Nr. 7 specifies S-plan-1 through
  S-plan-4: 20/20/40/40 items, 3/5/3/5 prompts, three models, two replicates,
  and two blocks. These are specification settings, not empirical anchors.
* **Estimands:** the prompt variance and gauge R&R in percent study variation.
* **Methods:** exactly one `msa_plan()` call per candidate, with `nsim` from
  ANK-06 and seed `20261108 + i` for candidate i. Within a candidate the
  simulations and REML fits are sequential. RNG is
  Mersenne-Twister/Inversion/Rejection. The default generator uses one worker;
  Unix callers may distribute whole candidates over workers. The results do
  not depend on scheduling. No simulation or fit is silently omitted.
* **Measures:** sample SD divided by mean of all prompt estimates, the share
  exactly equal to zero and its MCSE `sqrt(p * (1-p) / n_sim)`. Singular fits
  and zero estimates remain. The planning rule is computed from ANK-89, with
  no pass threshold for its difference from the empirical CV.

`replicates.csv.gz` has `plan`, `scenario`, `sim`, `estimate`, `singular`,
and `prompt`. The scenario number is the candidate's position; each candidate
has repetitions from one through `n_sim`. Doubles use `sprintf("%.17g")`, so a
tiny positive prompt estimate remains distinct from zero. `summary.csv` is
computed after reading those stored replicates back. It includes every
`msa_plan()` summary, design sizes, seeds, the planning-rule comparison, and
the supplementary CV MCSE. Quantiles use definition 7. `session.txt` and
`SOURCES.json` record methods, seeds, RNG, versions, source and function hashes,
elapsed times and result hashes. Source hashes describe the actual generation
run; they are not compared with the current product code by the reader.

The supplementary **CV MCSE uses a delta approximation**. For sample size n,
first raw moment m1 and second raw moment m2, let

```
g(m1, m2) = sqrt(n / (n - 1)) * sqrt(m2 - m1^2) / m1
gradient = sqrt(n / (n - 1)) *
  c(-m2 / (m1^2 * sqrt(m2 - m1^2)), 1 / (2 * m1 * sqrt(m2 - m1^2)))
MCSE(CV) = sqrt(t(gradient) %*% (cov(cbind(prompt, prompt^2)) / n) %*% gradient)
```

This requires a positive mean, positive variance and finite required moments.
Undefined supplemental MCSE values are explicitly labelled, never replaced
with zero. The finite-sample SD correction is included. The approximation is
allowed by ADR-054 Nr. 9 pending the operator's ACC-9 decision about the formula
collection; it introduces no acceptance threshold. Unit tests independently
derive the same delta variance using the mean and centered second moment.

Only ANK-89 is copied here, in full and byte for byte. ANK-06 is reused from
`validation/latent/anchors/`; ANK-16 and ANK-TOL from
`validation/numeric/anchors/`. All four copies and their provenance are checked.
With `REPO_ROOT` set, each original must also exist and match its recorded hash.
Missing or damaged files, incomplete keys, invalid estimates and summaries that
do not agree with the stored repetitions cause named errors.

From a source checkout with the frozen dependencies already installed:

```sh
Rscript data-raw/make_validation_planning.R
Rscript inst/validation/sim/planning_rule.R --package . --workers 1 --out inst/validation/planning
```

On Unix, `--workers 4` runs the same four seeded calls concurrently. With an
installed package, omit `--package` and choose an output directory outside the
installation. An independent rerun into another directory must produce the
same summary and replicate bytes; elapsed times and session metadata describe
each actual run separately. If `msa_plan()`, `msa_simulate()` or `msa_fit()`
changes numerical results, regenerate the files. Do not relabel old results
with a new code hash. Regenerating the anchor manifest also requires a new
generation run before the resources can be read as a complete study.
